## О проекте

- Автор: 1240TwlveThirty
- Референсы: Dead Cells, Rogue Prince of Persia (геймплей); Ori/Silksong (визуальный ориентир на будущее)

## Статус: вертикальный срез в разработке

### Реализовано

**Игрок (`player.tscn`)** — CharacterBody2D
- Движение полностью переведено на явный Finite State Machine (паттерн State через отдельные объекты-Node, не enum+match) — `player/states/`
- Состояния: Idle, Run, Jump, Fall, Land, Dash, Attack — каждое в своём файле, с методами enter()/exit()/physics_update()
- StateMachine — узел-диспетчер, хранит текущее состояние, метод transition_to(state_name) для переключения
- Двойной прыжок через счётчик jumps_used/max_jumps
- Рывок (Dash) — состояние с ограниченным временем жизни (таймер вместо условия выхода), кулдаун хранится в player.tscn.gd (тикает вне состояния Dash)
- Комбо-атака на 4 шага (не 3, изменено при разбивке анимаций) — комбо-логика внутри одного состояния Attack через player.combo_step, не отдельные состояния на каждый удар
- Приземление (Land) — короткое состояние-мост между Fall и Idle/Run для сглаживания анимации
- Legacy bool-флаги (is_dashing, is_attacking) и связанный процедурный код полностью удалены — FSM единственный источник истины о поведении игрока

**Враг (`enemy.tscn`)** — CharacterBody2D
- Hitstun/stagger при получении урона: is_staggered + stagger_timer (0.4с по умолчанию), блокирует атаку и преследование, прерывает начатый замах врага. Реализовано через явные переменные (не FSM) — осознанно, состояний пока мало (chase/attack/stagger)

**Арена (`arena.tscn`)** — Node2D, назначена как Main Scene
- Sprite2D-фон (временный арт, нарисован пользователем)
- Floor: StaticBody2D + ColorRect-заглушка
- Player и Enemy вложены как экземпляры сцен

### Ключевые архитектурные решения
- Hitbox/Hurtbox паттерн через Area2D — отделён от физических CollisionShape2D тел
- Группы (Groups) вместо жёстких путей к узлам (get_node) — слабая связанность
- queue_free() вместо free() — безопасное удаление в конце кадра
- Явная типизация вместо `:=` там, где тип неоднозначен (например, sign())
- @export для дизайнерских параметров — подбираются в инспекторе без правки кода
- State Machine (паттерн State) для игрока — каждое состояние отдельный класс-Node, наследуется от базового State. Выбран вместо enum+match ради изоляции логики состояний друг от друга при росте их числа
- StateMachine.start() вызывается явно из Player._ready(), а не автоматически в своём _ready() — из-за порядка инициализации Godot (дочерние _ready() выполняются раньше родительских, @onready-поля Player ещё не готовы в момент _ready() у StateMachine)
- Враг пока остаётся на явных bool/timer-переменных — сознательная отсрочка FSM до появления разных типов врагов

### Известные временные решения (техдолг, осознанный)

## 14.08.2026 — Покадровая анимация персонажа (заглушка)

Добавлен пиксель-артовый ассет "Black Knight" (Fellor/BitBlast Studio, лицензия
разрешает коммерческое и некоммерческое использование, атрибуция не обязательна)
как временная заглушка визуала игрока — не финальный арт.

Sprite2D заменён на AnimatedSprite2D. Создан SpriteFrames-ресурс с 7 базовыми
локомоционными анимациями: idle (3 кадра), run (4 кадра), jump (3), mid_air (2),
fall_light (3), fall_heavy (3), land (3). Только базовая локомоция — атаки,
parry, death, buff из пака ещё не подключены, будет отдельным заходом.

Известный технический долг: кадры разных анимаций имеют разную высоту
(run — 192px, остальные — 128px), из-за чего при centered=true возможен
небольшой визуальный "скачок" персонажа по вертикали при смене анимации.
Осознанно не занимались точной подгонкой якоря кадров — это заглушка,
решать будем на финальном арте у аниматора.

Добавлена временная функция `_update_animation()` в player.gd — прямое
условие if/elif на текущих булевых флагах (is_on_floor/is_dashing/velocity),
дёргает `AnimatedSprite2D.play()`. Это заведомо временный код-мост:
следующий шаг — рефакторинг движения на явный State Machine, после чего
эта функция будет переписана на основе состояний, а не разрозненных флагов.

Фоновая картинка в арене — декоративная концепт-арт заглушка, не привязана
по масштабу к игровым объектам, будет заменена при переходе к реальной
геометрии уровня (стены/полы).


### 15.08.2026 — State Machine для игрока, hitstun врага, комбо на 4 удара

Движение и боевая логика игрока полностью переведены с явных bool-флагов
на Finite State Machine (паттерн State: каждое состояние — отдельный Node
с enter()/exit()/physics_update()). Реализованы состояния Idle, Run, Jump,
Fall, Land, Dash, Attack. StateMachine хранит текущее состояние и метод
transition_to(name) для переключения между ними.

Обнаружен и исправлен архитектурный нюанс: StateMachine нельзя запускать
автоматически в своём _ready(), т.к. Godot вызывает _ready() дочерних узлов
раньше родительских — @onready-поля Player (например, animated_sprite) ещё
не готовы в этот момент. Решение — явный метод StateMachine.start(),
вызываемый из конца Player._ready().

Комбо-атака увеличена с 3 до 4 шагов — при разбивке анимации light-атаки
(единый спрайт-лист на 40 кадров) выяснилось, что в ассете 4 отдельных
удара, а не 3. Комбо-шаг остаётся внутренней переменной одного состояния
Attack, а не отдельными состояниями на каждый удар — разные удары
физически ведут себя одинаково, различаются только анимацией и уроном.

Врагу добавлен hitstun: при получении урона (через уже существующий сигнал
health_changed) враг на stagger_duration (0.4с) не может атаковать и
преследовать, текущий замах прерывается. Реализовано через явные
переменные, не FSM — у врага пока всего 3 ветки поведения, полноценный
State Machine отложен до появления новых типов врагов.

Дважды за сессию встретился один и тот же баг: дублирование блока кода
в _physics_process (у enemy.gd и у player.tscn.gd) после ручной вставки —
приводило к двойному выполнению логики за один физический кадр (в т.ч.
ложной поломке двойного прыжка). Взято на заметку: после вставки кода
проверять функцию через Ctrl+F на предмет случайного дублирования.

Легаси-код движения/атаки/дэша (is_dashing, is_attacking, _process_movement,
_start_attack и т.д.) полностью удалён из player.tscn.gd — FSM единственный
источник истины о поведении игрока.
Следующие шаги по плану: (1) явный State Machine для движения, (2) геометрия 
тестового уровня, (3) лазанье по стенам, (4) визуал врага той же связкой.
